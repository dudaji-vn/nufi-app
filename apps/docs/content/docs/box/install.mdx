## Before you start

| | |
|---|---|
| **Machine** | Ubuntu 24.04 or macOS. On Windows, run this inside WSL2 Ubuntu — the installer stops if you try it anywhere else. WSL2 puts the box behind a NAT the same way a virtual machine does, so other devices on the office network cannot reach it without a `netsh interface portproxy` forward; the from-home mesh works regardless. For a box the whole office reaches on the LAN, prefer a machine running Ubuntu or macOS directly. |
| **Network** | For a box that stays in one place, give it a fixed address (a DHCP reservation on the router, or a static IP). The box bakes its address into its certificate at install; if a plain DHCP lease later hands it a different one, `<name>.local` stops matching until you re-run `nufi-box announce`. |
| **Docker** | Engine plus Compose v2. On Ubuntu the installer offers to install Docker for you; on macOS install Docker Desktop or OrbStack first. |
| **git** | Any recent one (2.25 or newer; Ubuntu 24.04 ships 2.43). On macOS the first `git` command offers to install the Command Line Tools if they are missing; on Ubuntu, `sudo apt-get install -y git` if `git --version` says nothing. |
| **Memory** | On macOS, give the Docker VM at least **12 GB** (Settings → Resources → Memory). The installer warns below 11 GB and carries on. The box itself uses about 3 GB running. |
| **Disk** | Budget 30 GB. Most of it is the model and the images. |

A GPU is optional. Without one the box answers from the CPU, which works and is
slower; a machine serving a handful of people at once wants a GPU.

## On Windows, work inside WSL2

*Running Ubuntu or macOS directly? Skip this section — go straight to [Get the box](#get-the-box).*

The box is a Linux server, so on Windows you run everything **inside a WSL2
Ubuntu shell** — never in PowerShell or Command Prompt. Those cannot run the
installer: typing `./install-box.sh` in PowerShell does not install anything, it
just opens the `.sh` file in an editor (if you see VS Code start, that is the
sign you are in the wrong shell).

1. In an **administrator** PowerShell, install WSL2 with Ubuntu, then reboot if
   asked:
   ```powershell
   wsl --install -d Ubuntu
   ```
2. Open **Ubuntu** from the Start menu and finish its first-run user setup. From
   now on, every command below runs in this Ubuntu shell.
3. Give that shell Docker — either enable Docker Desktop's WSL integration
   (Settings → Resources → WSL integration → turn on your Ubuntu distro), or
   install Docker Engine inside WSL2. If you install the engine, run the two
   commands **one at a time**, not as a single paste.

   Install the engine first, and wait for it to finish — it takes a minute or
   two and prints a lot of output:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
   Once it is back at the prompt, add yourself to the `docker` group:
   ```bash
   sudo usermod -aG docker $USER
   ```
   Now **close the Ubuntu shell and open it again** — the group membership only
   takes effect in a new shell. Confirm it worked before going on; this should
   print an empty table, not a "permission denied" error:
   ```bash
   docker ps
   ```
4. Clone into your WSL2 home (`cd ~` first), **not** a Windows path under
   `/mnt/c/…`: a checkout made on the Windows side can carry CRLF line endings
   that break the shell scripts, and `/mnt/c` is slow.

Then follow **Get the box** and **Install** below exactly as on a native Ubuntu
machine, with a few WSL2 limits to know. WSL2 puts the box behind a NAT like a
virtual machine, so other devices on the office network cannot reach it on the
LAN without a `netsh interface portproxy` forward (the from-home mesh works
regardless). `--with-works`, `--self-host-coordinator` and `--egress-enforce`
need a real Ubuntu host, so they are not available under WSL2.

And **port 445 — the department drives (SMB) — is already taken by Windows' own
file sharing**, so Docker cannot bind it and the install stops with `ports are
not available: exposing port TCP 0.0.0.0:445`. The box itself does not need that
port (ingestion and the agents read the drive folders directly); it is only how a
member's computer mounts `\\<box>\<department>`, which WSL2's NAT makes awkward
anyway. Two ways past it:

- **Skip the member mount (simplest for a test):** before installing, point Samba
  at a free host port so it stops fighting Windows — in `deploy/box`, run
  `sed -i 's/"445:445"/"1445:445"/' docker-compose.linux.yml` — then install.
  Chat, the console and ingestion all work; only mounting the drives from another
  computer over SMB does not.
- **Keep the drives:** free port 445 by turning off Windows' own SMB server, in an
  **administrator** PowerShell — `Stop-Service LanmanServer -Force; Set-Service
  LanmanServer -StartupType Disabled` — then **reboot** (the kernel holds 445
  until then) and install. This disables Windows file sharing on that machine;
  re-enable it later with `Set-Service LanmanServer -StartupType Automatic;
  Start-Service LanmanServer`.

And **files the box writes live in the WSL2 Linux filesystem**, which Windows
File Explorer does not show by default — the clone, the `.env`, and the join
files `nufi-box invite` writes under `data/invites/` are all there. To open one
from Windows, run `explorer.exe` from the Ubuntu shell pointed at the folder —
for an invite, `cd ~/nufi-app/deploy/box/data/invites && explorer.exe .` opens
it in File Explorer. Or, in File Explorer, browse to the **Linux** entry in the
sidebar (address bar `\\wsl.localhost\Ubuntu\`). `nufi-box invite` prints this
reminder itself when it runs under WSL2.

For a box the whole office reaches on the LAN, install on a machine running Ubuntu
directly.

## Get the box

The box is three folders of one repository: `deploy/box`, and beside it
`deploy/platform/scenarios` — `nufi-box flows install` runs the routine
builder `studio/build_flows.py`, which imports `run_box` and `run` from the
folder above it — and `deploy/platform/adapters/nufi-cron`, which `nufi-box
schedule list` needs. Together they are about 1 MB. A sparse clone fetches
just those:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/dudaji-vn/nufi-app
cd nufi-app
git sparse-checkout set deploy/box deploy/platform/scenarios/studio deploy/platform/adapters/nufi-cron
cd deploy/box
```

This takes a few seconds on any link. Naming `scenarios/studio` in the set
also brings the files at the root of `scenarios/` (a sparse checkout always
includes a folder's parents) and leaves out `scenarios/demo`, twenty
megabytes of videos the box never reads.

Do not download the repository as one archive instead
(`curl … codeload.github.com … | tar -xz`): it is about 200 MB, of which
the box uses 1 MB, and on an office link that is ten to twenty minutes with
nothing printed — `curl -s` is silent while it waits, so it looks stuck.

## Install

```bash
./install-box.sh --yes
```

`--yes` takes every default. Drop it to be asked instead:

| Question | Default | What it decides |
|---|---|---|
| Box name | `nufi` | Yours to choose. Becomes the office address (`<name>.local`), the from-home address (`<name>.box.<domain>`) and the name on the certificate. Lowercase letters, digits and hyphens. Two boxes on one network or one coordinator must not share a name — see [On the LAN and from home](/docs/box/reaching#the-boxs-name) |
| Admin email | `admin@nufi.local` | The one login you use across all four products |
| Departments | `legal,hr,ga,strategy` | One drive folder, one team and one agent per name |
| Inference profile | `ollama` (macOS) or `ollama-docker` (Linux) | Where the model runs |

### Inference profiles

| Profile | Where the model runs |
|---|---|
| `ollama` | Ollama already on the host (macOS default) |
| `ollama-docker` | Ollama in a container the box manages (Linux default) |
| `remote` | Another machine on your network speaking the OpenAI API |
| `cloud` | A hosted provider. The only profile where text leaves the building. |

`ollama` and `ollama-docker` ask which model; the default is `qwen2.5:7b`.
`remote` and `cloud` ask for a base URL and a key.

### Changing the model later

There is no settings screen for this, and you do not edit `.env` by hand —
the model name is also baked into the gateway's rendered config, so an
`.env` edit alone would leave the two out of step. Instead re-run the
installer with the answers you want to change passed as environment
variables in front of it. It rewrites `.env`, re-renders the gateway config
and restarts the stack; the box keeps its name, accounts and all ingested
data (nothing is reinstalled).

To move a box onto a hosted model — useful when the machine is too slow to
answer from its own CPU — point it at any provider that speaks the OpenAI
API:

```bash
INFERENCE_PROFILE=cloud \
INFERENCE_BASE_URL="https://api.openai.com/v1" \
INFERENCE_API_KEY="<provider key>" \
INFERENCE_MODEL="<model id the provider serves>" \
./install-box.sh --yes
```

`cloud` is the one profile where text leaves the building. The embeddings
model keeps running locally; you do not pass anything for it.

To instead stay local but lighter — the quickest win on a weak machine — keep
the profile and only drop to a smaller model:

```bash
INFERENCE_MODEL="qwen2.5:3b" ./install-box.sh --yes
```

## How long it takes

Measured, not estimated:

| | |
|---|---|
| Blank Ubuntu 24.04, 4 vCPU, 8 GB, no Docker, nothing cached | **25 min 40 s** from the first command to the banner |
| A machine that already has the images and the model | **about 75 seconds** |

Nearly all of the difference is download. Docker Engine goes on, the installer
re-runs itself inside the new `docker` group, and the first image starts coming
down within two minutes.

## The banner is the result

```
  NuFi box "nufi" is up.

  Chat:        https://nufi.local:3080     (also https://<box-ip>:3080)
  Agents:      https://nufi.local:3001/choose
  Console:     https://nufi.local:3001
  Admin panel: https://nufi.local:3002
  Certificate: http://nufi.local/   ← laptops trust it once

  Admin login: admin@nufi.local / <generated password>
  Drives:      <data dir>/drives/<department>  → become that department's knowledge

  Day two:     nufi-box status | logs | drive add <name> | ca-cert | doctor
```

Four URLs, one login, and where the folders live. Write the admin password
down now — it is generated during the install and it is in `.env`, which is
created mode `0600` and holds every other secret the box has.

## If something goes wrong

```bash
./nufi-box doctor
```

It checks the things that actually break and says what to do about each in
plain words. Re-running `./install-box.sh` is safe: it keeps the answers already
on disk unless you override them explicitly.
