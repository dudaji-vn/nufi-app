title: Users

The **Users** tab is the canonical source of truth for who can use
NUFI in your organisation.

## List and search

The table shows everyone, paginated. Filters across the top:

- **Role** — `ADMIN`, `USER`, or custom roles you have defined.
- **Group** — show only members of a specific group.
- **Status** — active or disabled.

Search is full-text across email, name, and username.

## Create a user

Click **+ New user**. You need:

- Email (must be unique).
- Name.
- Initial password.
- Role (defaults to `USER`).
- Optional group membership(s).

Once saved, the user can sign in immediately. If your deployment
has email delivery configured, you can also send them a "welcome —
please reset your password" email instead.

## Deactivate vs delete

- **Deactivate** keeps the user record, their conversations, and
  their files, but blocks sign-in. Reversible.
- **Delete** removes the user, their conversations, their messages,
  their files, and revokes every API key they ever issued.
  Irreversible.

Prefer **Deactivate** for off-boarding. Reserve **Delete** for test
accounts and explicit right-to-be-forgotten requests.

## Impersonate

If you have the `IMPERSONATE` capability, the row menu has **Sign
in as**. Your session switches to the target user; you see exactly
what they see. The audit log records both your account and the
impersonated user on every action you take.

Impersonation is one-shot — sign out to return to your admin
account.

## Reset password

The row menu has **Reset password** with two modes:

- **Set new password** — type a value, save. The user sees the new
  password on next sign-in.
- **Send reset link** — emails the user a one-time link. Requires
  email delivery configured.

If 2FA is enabled, the row menu also has **Reset 2FA** to clear the
TOTP secret. The user re-enrols on next sign-in.

## Bulk import

CSV import lives under **+ New user → Import**. Required columns:
`email`, `name`. Optional: `password`, `role`, `groups`. Missing
passwords trigger a one-time-link email (if email is configured) or
fail (if not).

## Audit

Every create / deactivate / delete / impersonate is recorded with
the acting admin's identity and timestamp. Visible under the
**Audit** tab.
