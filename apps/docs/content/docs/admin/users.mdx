---
title: Users and membership
description: Where user accounts come from and how you assign them roles and groups.
---

People get a NUFI account by **signing in to the app** at
`chat.nufi.me` (self-registration or SSO, depending on how you've set
up [Configuration → Features / Registration](/docs/admin/configuration)).
As an admin, you don't create accounts in a separate "Users" screen —
you control what each person can do by assigning them to **roles** and
**groups** on the [Access](/docs/admin/roles-and-groups) page.

## Give someone admin powers

<Steps>
<Step>Make sure the person has signed in to the app at least once so
their account exists.</Step>
<Step>Open **Access → Roles** and click the role you want them in
(e.g. `ADMIN`, or a custom sub-admin role).</Step>
<Step>Go to the **Members** tab and add them.</Step>
<Step>Save. They pick up the role on their next request — no sign-out
needed.</Step>
</Steps>

![The Members tab lives inside each role on the Access page](/screenshots/admin-role-detail.png)

To **remove** someone's powers, open the role's **Members** tab and
remove them; they fall back to the default `USER` role.

## Give a set of people different features or limits

Use a **group** rather than editing people one by one:

<Steps>
<Step>On **Access → Groups**, create a group and add the members.</Step>
<Step>In [Configuration](/docs/admin/configuration), add a scoped
override for that group — a model, a feature flag, a higher cap.</Step>
</Steps>

See [Scoped overrides](/docs/admin/scoped-overrides) for how the
override resolves.

## What about budgets, API keys, and usage?

Per-user **budgets, rate limits, and API keys** are managed in the
gateway and surfaced to each user in their own
[console](/docs/end-user/api-keys). For org-wide model access and
limits, use **Configuration** plus group overrides; for the gateway's
own admin UI see [Gateway admin](/docs/admin/litellm).

> The roles available when you assign membership are the ones defined
> on [Access](/docs/admin/roles-and-groups); the capabilities each role
> carries are set on [Grants](/docs/admin/capabilities).
