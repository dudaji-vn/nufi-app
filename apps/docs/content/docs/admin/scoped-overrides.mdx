---
title: Scoped overrides
description: How role-, group-, and user-level overrides cascade.
---

Most fields under [Configuration](/docs/admin/configuration) accept
**scoped overrides** in addition to the base value. When a user
makes a request, NUFI resolves the value for that specific user by
walking the override stack.

This page covers the resolution rules and a worked example.

## The four scopes

| Scope    | When it applies                                            |
|----------|------------------------------------------------------------|
| `BASE`   | Always — this is the default                               |
| `ROLE`   | When the user has the matching role                        |
| `GROUP`  | For each group the user belongs to                         |
| `USER`   | Only for the named user                                    |

## Priority

Every override carries a numeric **priority**. Lower priority wins.
The order is:

1. Among `USER` overrides for the field, pick the one with the
   lowest priority.
2. If no `USER` override matched, repeat for each of the user's
   `GROUP` overrides — pick the lowest priority.
3. If no `GROUP` override matched, try the user's `ROLE` override.
4. If still nothing matched, use the `BASE` value.

The scope hierarchy is **not** a tie-breaker: `USER` always beats
`GROUP` which always beats `ROLE` which always beats `BASE`.
Priority only breaks ties within the same scope.

## A worked example

Say total upload size per conversation:

- `BASE = 50 MB`
- `ROLE: USER` → `100 MB` with priority 10
- `GROUP: power-users` → `200 MB` with priority 5
- `GROUP: beta-testers` → `500 MB` with priority 1
- `USER: alice@org` → `1 GB` with priority 0

For alice (in both groups, role `USER`):

1. `USER` override: `1 GB` → matches → resolved.

For bob (in `power-users` only, role `USER`):

1. `USER` override: none.
2. `GROUP` overrides: `power-users → 200 MB`. Resolved to `200 MB`.

For carol (in `beta-testers` and `power-users`, role `USER`):

1. `USER`: none. `GROUP` overrides: `power-users (prio 5)` and
   `beta-testers (prio 1)`. Lowest priority wins → `500 MB`.

For dave (no groups, role `USER`):

1. `USER`: none. `GROUP`: none. `ROLE`: `USER → 100 MB`. Resolved
   to `100 MB`.

## When to use which scope

- **`ROLE`** — broad defaults that follow people as roles change.
  Example: every `USER` gets 100 MB, every `ADMIN` gets 500 MB.
- **`GROUP`** — targeted feature flags or capacity bumps for a
  known set of people. Example: members of `beta-testers` see a
  new model in the dropdown.
- **`USER`** — exceptions. Example: a paid customer asked for 1 GB.

If you find yourself with dozens of `USER` overrides for the same
field, that is the signal to create a `GROUP` and consolidate.

## Removing an override

Click the gear next to the field, find the override in the popover,
**Delete**. Removal is immediate.

## Auditing the cascade

The **Field profile popover** is the easiest way to debug "why is
this user seeing 100 MB?" — it shows every active override on the
field, sorted by priority, with the winning one highlighted.
