A conversation is a good way to solve a problem once. When you find
yourself solving the same shape of problem every week — the same
extraction from a different invoice, the same answer from a growing set
of documents — the useful thing is not a better prompt. It is a
pipeline you can run again, hand to a colleague, and call from code.

That is what Studio builds.

## The pieces

Studio is a canvas. You drag **components** onto it and connect them.
Each component does one thing and has typed inputs and outputs, so a
connection either makes sense or the canvas will not let you make it.

| | |
|---|---|
| **Flow** | One pipeline. The thing you build and run |
| **Component** | One step — a model, a prompt, a document loader, a tool, a piece of logic |
| **Playground** | Where you run the flow and watch what each step produced |
| **Deployment** | A published flow, reachable over the API |
| **Knowledge** | Document sets a flow can search |

The left side of a flow lists the components available to you, grouped
by what they do. The canvas is the flow itself. Everything runs when
you press run — not as you edit.

## Your first flow

The shortest flow that does something real has three parts: something
that takes input, a model, and something that returns output.

<Steps>
<Step>From the home screen, create a new flow. Starting from a template is
usually faster than starting blank — the templates are working flows you
can take apart.</Step>
<Step>Drag a **model** component onto the canvas and pick a NUFI model.</Step>
<Step>Connect an input to the model, and the model to an output.</Step>
<Step>Open the **Playground**, type something, and run it.</Step>
</Steps>

If nothing happens, open the component that failed — it reports its own
error in place, and the message is usually specific about which input it
did not get.

## Working with your own documents

A model on its own answers from what it learned. To answer from *your*
material, the flow needs a retrieval step: something that finds the
relevant passages first and passes them to the model with the question.

Build it in this order, because each step is worth checking before the
next one is added:

1. **Load** the documents.
2. **Split** them into chunks. Chunks that are too large blur the
   answer; too small and they lose their context.
3. **Embed and store** them, so they can be searched by meaning.
4. **Retrieve** the closest chunks for the question.
5. **Prompt** the model with the question and those chunks.

Run it after step 4 and read what comes back before wiring in the model.
If retrieval returns the wrong passages, no prompt will save the answer —
and it is far easier to see that on its own than through a model's
paraphrase of it.

## Publishing a flow

A flow that only runs in the Playground is a prototype. Publishing it
turns it into an endpoint your own code can call, with the flow doing
the work behind it.

Studio gives you the URL and the shape of the request. You will need an
API key from Studio's own settings to call it.

<Callout type="warn">
A published flow runs with whatever access it was built with. Before you
publish one that touches a knowledge base, be clear about who can reach
the endpoint — anyone who can call it can ask it anything, including
questions the documents can answer but the caller should not be asking.
</Callout>

## Variables and secrets

Do not paste credentials into a component field. Studio has **global
variables** in settings for exactly this: store the value once with its
type set to **Credential**, and reference it from the component by name.
A Credential variable is encrypted at rest and is not readable back
through the UI, so it does not travel with the flow when the flow is
exported or shared.

## What Studio does not do

- **It does not sandbox what a flow runs.** A flow executes inside
  Studio itself. Components that run code or reach the network do so
  with Studio's access, not inside an isolated environment. Treat a
  flow you did not write the way you would treat a script you did not
  write.
- **It does not share your flows automatically.** Flows are yours until
  you export or publish them.
- **It is not where agent work is tracked.** Goals, assignments and
  approvals live in NUFI Works.

## When things go wrong

| What you see | Usually means |
|---|---|
| A component shows an error and the run stops | An input it needed was empty or the wrong type. The message names it |
| The flow runs but the answer ignores your documents | Retrieval returned nothing. Run the retrieval step alone and look at what it found |
| A model component fails to connect | The model is not enabled for your account. See [Pick a model](/docs/end-user/models-and-presets) |
| Everything is slow on a large document set | Embedding runs once per chunk. It is slow the first time and fast afterwards |
